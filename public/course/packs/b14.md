# 照片 → 3D 建築（photo-to-3d-building）

## 輸入
- `input/建築照片/`：一張或多張建築照片（練習用已放一張虛構示意照片）
- `input/campus.html`：3D 場景起始檔（Three.js，已有地面、燈光、鏡頭、點選介紹與導覽按鈕，以及一棟範例 `buildSample()`）
- `input/建築細節_範本.json`：JSON 骨架（含 construction／math／elevation 三段的完整範例）
- `input/範例_立面圖.svg`：範本 JSON 產生的座標尺寸立面圖（對照用）
- `tools/elevation_svg.py`：把 JSON 的 `elevation` 轉成立面 SVG 的程式

## 階段一：照片 → 建築細節 JSON
1. 由大到小拆解構件：**量體 → 立面 → 門窗 → 屋頂 → 招牌 → 裝飾 → 地面 → 植栽**。
2. 每個構件標記 `evidence`：
   - `observed`：照片中清楚看得到
   - `estimated`：看得到但需推估（例如尺寸、樓層高）
   - `occluded`：被遮住（樹、車、其他建築）
   - `unknown`：照片完全看不到
3. 規則：
   - 尺寸一律標為推估（`"unit": "m", "evidence": "estimated"`），並寫出推估依據（例如「以門高 2.1 m 為比例尺」）。
   - 看不清楚的字填 `null`，不猜。
   - 不推論樹種，只寫「喬木／灌木／草地」與大約高度。
   - 看不到的一側**不自動鏡像**，標 `unknown`。
4. 每個構件附照片區域座標 `bbox: [x, y, w, h]`（0–1 比例，左上角為原點）。
5. **建築工法分析**（JSON 的 `construction`）：
   - 結構系統（例如 RC 梁柱構架、鋼構、加強磚造）、外牆系統（磁磚、清水模、帷幕牆）、開口（窗框材質、分割）、雨遮或懸挑、屋頂（平／斜、女兒牆、防水與排水）、基礎、耐震。
   - 每項寫 `value`、`evidence`、`basis`（從照片哪些特徵推得）。
   - 看不到的（基礎、防水、耐震）一律 `null`＋`unknown`；**不判定結構安全、耐震能力或法規符合性**，註明需由結構技師或建築師確認。
   - 加一句 `modeling_hint`：這種工法在 3D 裡用什麼方式建。
6. **數學演算法分析**（JSON 的 `math`）：
   - `camera_model`：判斷是平視正立面（可直接比例換算）、兩點透視或仰視；需要時用立面四角點求單應矩陣（homography）把立面拉正。
   - `scale`：至少用 **2–3 個參考物**（門高、窗高、樓層高、磁磚、欄杆、人）各算一次 m/px，取**中位數**；偏離大的參考列出原因與「需確認」。寫明誤差範圍（例如 ±15%）。
   - `formulas`：列出實際用到的換算公式（像素 → 公尺、照片座標 → 立面座標、窗戶等差數列 xᵢ = x₀ + i·d、樓層高、寬高比檢查）。
   - `algorithms`：說明用了哪些方法（比例尺交叉驗證、窗格最小平方擬合、對稱軸、透視校正），每個方法一句「怎麼做」。
7. **座標尺寸 SVG 分析**（JSON 的 `elevation`＋SVG 檔）：
   - 立面座標系：原點＝正立面左下角，x 向右、y 向上，單位公尺。
   - 寫出量體寬高、女兒牆高、樓層線、窗戶（`x0`、`dx`、`w`、`h`、各列 `row_y`、被取代的 `skip`）、門、雨遮、招牌的座標與尺寸。
   - 執行 `python3 tools/elevation_svg.py output/建築細節_<代號>.json output/立面_<代號>.svg`，產出有 1 m 格線、座標標註與尺寸線的立面圖；打開 SVG 檢查窗戶數量與照片一致、標示「推估」。
   - SVG 的尺寸與 JSON 必須一致；階段二建模時直接沿用這組座標。
8. 輸出 `output/建築細節_<建築代號>.json` 與 `output/立面_<建築代號>.svg`（格式見範本）。
9. 交付後最多問 **3 題**，已經說清楚的就不問：
   - 這棟在校園（院區）的位置？
   - 招牌文字對不對？
   - 要直接建模，還是先修改 JSON？

## 階段二：逐一建立 3D 建築
0. 尺寸與位置一律沿用階段一 `elevation` 的立面座標（立面座標 x → 3D 的 x，y → 3D 的 y，立面中心對齊群組原點）。
1. 每張照片建立一個獨立的 `buildXxx()` 函式（例如 `buildAdminHall()`），**一次一棟，彼此不覆蓋**；在 `BUILDINGS` 陣列登記一筆。
2. 位置：
   - 能對上 campus.html 原有建築時，保留原本的長度、方向與位置，只換外觀。
   - 位置不明時，建成可搬移的獨立群組（`THREE.Group`），放在空地，介紹文字標註「位置待確認」。
3. 建模對照表：

| 照片中的構件 | 建模方式 |
|---|---|
| 大量重複的窗戶 | `InstancedMesh`（一個幾何＋一個材質，矩陣排列） |
| 曲線池緣、花台 | `Shape` → `ExtrudeGeometry` 擠出 |
| 壁畫、海報 | `CanvasTexture` 或圖片貼圖貼在平面上 |
| 浮雕 | 以牆面座標建立 `Group`，子物件用牆面局部座標排列 |
| 中文立體字（招牌） | `CanvasTexture` 文字平面疊 3–5 層，每層微小 z 位移產生厚度 |
| 屋頂女兒牆 | 四段細長 `BoxGeometry` |
| 植栽 | 樹幹圓柱＋樹冠球體或圓錐，只用大約高度 |

4. 常見陷阱：
   - 平面場地（操場、廣場）高度要比地面高 0.01–0.02，避免與地面閃爍（z-fighting）。
   - 招牌與立面要朝向鏡頭預設方向；確認正面朝向（+z 或依原建築方向）後再放字。
   - 照片多為仰視：屋頂細節常看不到，標 `unknown`，不要自行補上複雜屋頂。
   - 單位一律公尺；新建築不可蓋在既有建築的位置上。
5. 每棟自動加上：點選介紹（名稱、用途、推估與待確認事項）、教育提示（`edu`）、鏡頭焦點（`focus`）與導覽按鈕。
6. 每次修改後：
   - 檢查 JavaScript 語法；
   - 在瀏覽器實際執行，確認主控台沒有錯誤、每棟 `buildXxx()` 都建得出來；
   - 交付完整的 `output/campus.html`，並列出：哪些尺寸是推估（附比例尺與誤差）、工法推估依據、哪些構件是 occluded／unknown、哪些位置待確認。

## 規則
- 只讀 input/，只寫 output/；原始照片不可修改。
- 照片中若有人臉、車牌，JSON 只寫「行人」「車輛」，不描述個人特徵，也不建模。

## 📱 手機版使用方式（ChatGPT／Gemini App）
1. 打開 ChatGPT 或 Gemini，按「＋」上傳這份檔案，以及範例資料（Excel／CSV／PPT／Word／圖片）。
2. 輸入：「請依照這份檔案執行」。
3. 沒看到可下載的檔案時，輸入：「請給我 Excel 檔」或「給我 CSV」。
